  • macro library lib/Ecs.xtlm: Ecs: its macro library -- c_omponents<, a world's layout written from its list of components. Imported with the functions, under one alias: "ec:" u_se< "Ecs". A macro is a function from the source text on each side of its call to the source that replaces the call, run before the program is compiled (X_eTaL MC10); this one creates names, which a function cannot. Names with m: are macros; those under h: are private to this file.
  • library lib/Text.xtl: Text: printing lines, shared by the games.
  • library lib/Board.xtl: Board: square boards as arrays, shared by the games. Rows and columns count from 0; a square's number counts from 1, row by row.
  • library lib/Ecs.xtl: Ecs: an entity-component system as arrays, shared by the games built on it. A world is one matrix of numbers: a row per entity slot, and columns for its fields. Column 1 says whether the slot holds a living entity (1) or is free (0); each component then takes a column saying whether the entity has it, followed by its fields. Entities are row numbers. A system is a whole-column expression: every entity with the components it needs, at once. The macro library Ecs.xtlm, under the same alias, writes a world's layout from a list of components (getters, setters, masks); these are the functions any world uses.
  • library lib/Play.xtl: Play: reading what a player types at the terminal, shared by the games' play.xtl programs. Every function prints its prompt, reads a line ([]R_EAD) and returns what it found; it never asks again itself (a game decides what is acceptable and asks again).
  • library lib/State.xtl: State: changing items of a game's state vector, shared by the games.
  • library lib/Svg.xtl: Svg: pictures written as SVG text, and the clicks on them, shared by the games played by clicking a map (capitals, stargazer). A picture's view v is x, y, width and height in the game's own units (its viewBox); layout is scaled to the view (l:u_nit), so buttons, menus and text look the same at every zoom. Rectangles are rows of x, y, width and height.
  • system macros std/System.xtlm: The system macros (lang-choices MC18, MC19, MC24), loaded before every file with no import and no alias: each is called unprefixed, as "c" i_f< "a; b". A macro is a function of the source text on each side of its call; the text it gives replaces the call. @ on a side means the macro takes nothing there (MC22). What only the compiler knows comes from hooks (MC20), usable only in a macro body.
  • program games/horse-race/horse-race.xtl: Horse race: a scripted race (seed 1) with the rules of HorseRace.xtl.
  • library games/horse-race/HorseRace.xtl: The horse race's rules, a library: horse-race.xtl (a scripted race), play.xtl (at the terminal) and the web page all use these. Five horses, a track of 15; every round each horse runs 1, 2 or 3 at random, all at once: the field is one vector of positions and a round is one expression. The first round in which any horse reaches the finish ends the race; the horses furthest along win (there can be a tie).
